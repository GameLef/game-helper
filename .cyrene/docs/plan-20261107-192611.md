# 计划：Python 客户端迁移至 Rust + GPUI Kit 原生桌面应用

> **归档计划｜2026-11-08 更新：** 本文保留迁移前调研与阶段验收设计。用户最新要求完全删除 Python 端，只保留 Rust 客户端与现有 AHK 执行后端；该要求覆盖本计划原有的保留 Python、延后删除和回退约定。Python 客户端、依赖与回退入口已删除，`start.bat` 统一启动 Rust，无 Python 回退。历史调研中的旧文件名只描述迁移前快照，不代表当前文件或运行依赖。入口已切换，真实验收仍按实际证据保留待办。

## 目标与审批范围

将 `E:\Project\github\game-helper` 中 Python 客户端的管理器、取点工具、数据模型及 Windows 集成迁移到 Rust，以 GPUI Kit 重建原生桌面界面。最终日常运行无需 Python/PySide6。

**GPUI Kit 可以直接构建原生桌面应用，无需 Tauri。** GPUI 负责系统窗口、GPU 绘制和输入事件，GPUI Kit 提供组件与应用入口。通过 Cargo 编译得到 Windows `.exe`，不引入 Tauri、WebView 或 HTML/CSS/JavaScript 前端工程。开发构建需要 Rust/MSVC 等工具，用户运行客户端不需要安装 Rust。

**本计划采用的迁移边界：Rust 管理与取点，继续复用 AHK v2 daemon/runner 执行路线。** 因此发布形态为原生客户端 exe 加 AHK 脚本和数据目录，路线执行仍依赖 AutoHotkey v2；本次不承诺把整个工具链打成完全无外部依赖的单文件 exe。

该边界已在用户本轮“根据这个计划文档继续执行任务”的授权下继续实施；将 AHK 执行核心也改成 Rust 仍会扩大范围。2026-11-08 当前进度：核心与 Windows 适配已接入，原生管理器和独立取点工具已有可编译运行的预览实现，Cargo 工作区测试日志报告 60 项通过，原生编辑/错误保护/失焦采点已做隔离观察。按最新要求，Python 端已删除，默认入口已切换为 Rust；真实 AHK 完整闭环、IME、多 DPI 等验收仍待完成，各阶段复合验收项暂不整体勾选。详细实现、诊断证据与剩余项见 `docs/rust-migration.md`。

## 目标架构与界面方案

### 原生 Rust 工程

运行结构为：**Rust + GPUI Kit 原生客户端 → Win32 通信 → AHK daemon/runner**。

仓库根已建立 Cargo workspace；原迁移期保留 Python 回退的要求已由最新删除要求覆盖，当前只保留 Rust 客户端与 AHK 执行后端：

```text
Cargo.toml / Cargo.lock / rust-toolchain.toml
crates/
  game-helper-core/       路线、校验、配置、缓存、文档状态
  game-helper-windows/    Win32 窗口、坐标、热键、AHK 进程与 IPC
  game-helper-desktop/    GPUI Kit 界面、命令、异步任务、exe 入口
scripts/                 开发与便携发布脚本
```

依赖方向：desktop → core/windows，windows → core；core 不依赖 GPUI 或 Windows API。

- UI 依赖 `gpui-kit = "=0.9.0"`，按需启用 `tree-sitter-yaml`，测试支持放开发依赖；提交 Cargo.lock，避免混用不同来源的 GPUI 类型。
- 数据采用 `serde`、`serde_json`；YAML 优先采用 YAML 官方组织维护的 `yaml_serde 0.10`，实施时用已有样本验证标量、浮点与错误定位语义后锁版本。
- Windows 使用 `windows` crate 和系统原生结构定义，集中封装 unsafe，避免手写错误 ABI。
- 异步采用 GPUI 任务/后台执行器与专用 Win32 热键线程，无需额外引入服务端运行时。
- 一个 `game-helper.exe`，默认管理器，`--picker` 启动独立取点进程，保留原来的独立生命周期。关闭管理器默认保留 daemon；关闭取点工具释放其热键和线程。
- 使用 GPUI 原生文件对话框、剪贴板和窗口能力；无需浏览器进程、前端资源服务器或 Tauri 桥接层。

### 界面与交互

采用 GPUI Kit 官方明暗主题、紧凑工具布局。顶部 daemon 控制条，左侧路线列表，右侧路线属性与“点位编辑 / YAML 源码”页签，底部执行与状态区，支持调整分栏尺寸。

| 区域 | 迁移内容 |
|---|---|
| 路线列表 | 文件/名称/点数/热键；无效文件可见并展示错误；新建/删除/导入/导出/定位文件 |
| 路线属性 | 名称、备注、process/windowClass/title 编辑，校验至少一个目标条件 |
| 点位编辑 | 新增、删除、上下移动、名称/备注、坐标；操作列表和 click/key/press/wheel/drag/wait 六类参数 |
| YAML | 原生 Editor、行号、YAML 高亮、语法和业务错误定位，与结构化视图受控同步 |
| daemon | 启动、停止 daemon、重载、自启、PID/热键数/busy、单步 done/total |
| 执行 | 从头、从第 N 点、仅第 N 点试跑；daemon 缺席时确认后使用 runner |
| 取点 | 窗口刷新/准星、屏幕/客户区/归一化坐标、热键采点、点名编辑/复制/删除、保存/导出 |

“停止 daemon”和“路线急停”分开表达。保留 AHK `hotkeys.stopAll` 急停能力，显示配置中的实际快捷键，默认 F12。原有无效“终止”按钮改为清楚的急停快捷键说明，不使用 reload 冒充中断；本次不新增 AHK 程序化急停协议。

## 兼容契约与失败处理

### 数据与 IPC

- 保持 `route/v1`、目标字段名、点位列表顺序、六类操作、默认值和业务校验。`startAt`/`only` 按列表中的 1-based 位置解释，不能当作 point.id。
- `ms/delta/duration` 接受满足整数性的整数或浮点；`id/clicks` 保持整数约束；数字字段拒绝 bool。坐标范围与点位 pos 六位小数纳入回归。
- 缓存与绑定继续用源文件 stem，兼容中文、空格、`-6`；JSON 验证语义、默认值与 UTF-8，不要求对象键序和空白字节一致。
- 通过相同字符串动态注册 `GameHelperDaemon_Ping`、`GameHelperDaemon_Reload`、`GameHelperDaemon_Stop`；Ping 保持 `(热键数 << 1) | busy`。
- `WM_COPYDATA` 保持 `dwData=1`、UTF-8 JSON `{route,startAt,only}`、`cbData` 包含 NUL，使用系统 `COPYDATASTRUCT`，发送期间维持缓冲区有效。
- `state/cursor.json` 由 AHK 写，Rust 只读并兼容有/无 BOM；单步成功推进、失败停留、回绕、reload 重置沿用原行为。
- 心跳约 2 秒、游标约 1 秒、坐标约 50ms；后台任务随所属窗口关闭而取消。
- 保持客户区物理像素及 `(width-1)/(height-1)` 换算，分清 GPUI 逻辑像素与 Win32 物理坐标。无效/最小化/零尺寸窗口、客户区外光标禁止生成非法点位，并展示原因。

### 文档、文件与生命周期

- 内存文档管理模型、原始源码、脏状态和磁盘版本；视图切换失败保留输入；切路线、关闭、执行前处理未保存修改，执行使用经校验且明确保存的数据。
- 源码模式保存已校验原文；纯浏览/切视图不写文件。结构化编辑生成规范 YAML，可能改变排版或移除注释，保存前提示并留备份；本次不承诺任意 YAML 的无损语法树编辑。
- 配置保留未知字段，只写实际变化；写前检测磁盘冲突，以临时文件和原子替换保存，冲突时阻止静默覆盖。`ahkPath` 优先于默认路径/注册表探测。
- `routesDir` 保留现值 `routes`；执行端仍固定 `routes/_cache`，其他配置值提示暂不支持，避免两端路径不一致。
- 根目录统一解析：显式 `--app-root` 优先，其次便携 exe 所在目录，开发模式向上定位含 `ahk/`、`config.json` 的根。失败提示选择，不默默在当前目录创建数据。AHK 使用正确脚本、绝对参数及 `cwd=ahk/`。
- 新建为内存草稿，合法后保存；重名导入提供取消/另存/确认覆盖；删除协调源文件、绑定、缓存和编辑器状态，部分失败如实报告。
- Rust 管理器单实例，取点模式独立控制实例与热键；验证用项目内隔离副本，通过磁盘冲突检查防止其他进程并发覆盖配置。不主动结束用户进程。

### 系统与通信错误

- 文件 IO、进程等待、消息发送放后台，IPC 有界等待，无响应时 UI 仍可交互。
- 发送超时视为结果未知，不自动重发执行请求。“受理成功”与“整条执行完成”分别表达，COPYDATA 返回 1 仅证明受理。
- busy 时限制重复执行；执行中重载/重绑排队到空闲或提示，避免隐式重置游标。
- 采点使用专用 `RegisterHotKey` 消息线程，退出注销；热键占用时显示冲突并保留采点按钮，防止局部/全局通道重复采样。首版不引入静默低级键盘钩子退路。
- 沿用与目标程序相应的权限启动方式，权限不足给出明确错误，不绕过 UIPI。DPI manifest 与 GPUI 初始化一致，在创建窗口前确定策略。
